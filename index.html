Recurrent Memory Lab

Teach a model a new mapping by writing demonstrations into a fixed-size state. Then query that state, inspect what was stored, and deliberately make it fail.

Falsifiable claimAdding demonstrations can be absorbed into a fixed-size recurrent state, but overlapping evidence can interfere and cause retrieval errors.

1. Give it demonstrations

Each demonstration writes one key→value association into the same matrix state.

2. Change the memory dynamics

Move similarity upward to make distinct keys share representational features. That creates crosstalk instead of giving every example a private slot.

3. BDH / BDH-CQ bridge

This interactive system is a toy teaching model, not an official BDH checkpoint. It illustrates the shared idea of evolving state.

Mt = λMt-1 + α ktvtT

The toy writes a key/value outer product into a fixed state. BDH's official formulation is richer: its working memory during inference relies on synaptic plasticity and Hebbian updates. BDH-CQ goes further by continuously updating recurrent memory from inference-time inputs and solving the query with iterative latent computation.

Do not equate the toy equation with the BDH implementation. The mapping is conceptual and explicitly labeled here.

What just happened?

Write: the current demonstration changes the same state matrix rather than appending a permanent memory slot.
Carry: after a write, the matrix remains the same 5×5 size; the sequence length grew, but state shape did not.
Read: the query vector probes the accumulated state. The output is a score over candidate values.
Interfere: similar keys activate overlapping directions. A later write can therefore strengthen the wrong answer for a neighboring query.

60-second learner test

Load the clean preset → query B → note the correct answer → raise key similarity → add the conflicting demo → query B again. The claim passes only if the interface makes it possible to observe both fixed state size and interference.
